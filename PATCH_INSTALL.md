# Патч Bike Rental: тарифы, продление и уведомления

Патч подготовлен поверх `bike-rental(4).zip`.

## Что входит

- Тарифы для каждого байка: 1 / 3 / 7 / 14 / 30 дней. Ставка задаётся **за один день**.
- Для точного срока 3, 7, 14 или 30 дней используется соответствующая ставка на весь период.
- Для любого другого срока используется базовая цена `daily_price` на каждый день.
- Быстрые варианты срока в форме бронирования; акционная ставка ниже базовой отображается с зачёркнутой базовой ценой.
- Сумма основного периода и сумма продлений хранятся отдельно.
- Продление активной аренды владельцем парка через раздел «Заявки» → «Активные» → карточка аренды → «Продлить аренду».
- Напоминания клиенту и владельцу за 3 дня и за 1 день до даты возврата.
- Напоминания отправляются через Telegram-бот конкретного парка, если у парка сохранён токен.
- На карточке байка показывается ожидаемая дата возврата, если байк сейчас находится в аренде.
- Байк автоматически получает статус «В аренде» в день начала подтверждённой аренды.
- Фотографии и видео при создании карточки отправляются в одном запросе вместе с данными карточки; экран блокируется индикатором сохранения.
- При создании заявки добавлена блокировка параллельных запросов на один байк на уровне PostgreSQL advisory lock.

## ВАЖНО: порядок установки

1. Сделайте резервную копию текущей PostgreSQL-базы в Render.
2. **До деплоя backend** выполните SQL из `backend/migrations/005_rental_pricing_extensions.sql` на текущей рабочей базе. Это additive migration: она добавляет колонки и таблицу истории продлений, не удаляя старые данные.
3. Распакуйте содержимое ZIP в корень вашего проекта `bike-rental`, сохраняя структуру папок и заменяя только перечисленные файлы.
4. Проверьте `git status`, затем выполните:

```powershell
git add backend frontend
git add PATCH_INSTALL.md
git commit -m "feat: rental pricing tiers and extensions"
git push
```

5. Дождитесь успешного деплоя Render и Vercel.

Не удаляйте старые миграции и не пересоздавайте PostgreSQL. Старые байки сохранят прежнюю `daily_price`; новые тарифы для 3/7/14/30 дней у них останутся пустыми, поэтому будет использоваться прежняя базовая ставка.

## Проверка после деплоя

1. Откройте редактирование байка и задайте базовую цену и тарифы 3/7/14/30.
2. Проверьте расчёт на 3, 7, 14 и 30 дней, а также произвольные 5 или 10 дней.
3. Создайте тестовую заявку, проверьте, что владелец получил сообщение от бота своего парка.
4. Подтвердите заявку и проверьте статус байка и даты аренды.
5. В активной заявке нажмите «Продлить аренду», введите новую конечную дату и проверьте раздельные суммы.
6. Проверьте карточку байка у клиента и владельца: отображается дата возврата.
7. Проверьте создание новой карточки с фото и видео.

## Ограничения проверки

- Backend Python-файлы прошли синтаксическую проверку `py_compile`.
- Полную сборку Vite/TypeScript в среде подготовки подтвердить не удалось: в архиве нет установленных frontend-зависимостей (`react`, `vite`, типы React). Поэтому перед production-деплоем дождитесь штатной сборки Vercel и не игнорируйте её ошибки.
- Фактическую отправку Telegram-сообщений и работу SQL-миграции на вашей Render-базе нельзя подтвердить без доступа к вашему серверу и базе.
