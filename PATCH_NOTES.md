# Bike Rental — исправления тарифов, бронирования, медиа и аналитики

Архив содержит только изменённые исходные файлы. Распаковать его поверх корня проекта `C:\Users\User\Desktop\bike-rental`.

## Что изменено

### 1. Тарифы за день по диапазонам

Расчёт теперь одинаковый в интерфейсе и Backend:

- 1–2 дня: базовая `daily_price`;
- 3–6 дней: `price_3_days`;
- 7–13 дней: `price_7_days`;
- 14–29 дней: `price_14_days`;
- 30 дней и больше: `price_30_days`.

Итог = количество календарных дней аренды (включая начальную и конечную даты) × ставка выбранного диапазона.

Для примера с базовой ставкой 500 000 VND укажите в карточке байка:
- базовая цена: 500 000;
- поле «3–6 дней»: 450 000;
- поле «7–13 дней»: 420 000;
- поле «14–29 дней»: 400 000;
- поле «30+ дней»: 350 000.

Тарифы хранятся в карточке каждого байка. Если поле тарифа пустое, Backend использует базовую цену этого байка. Новая SQL-миграция не требуется.

### 2. Защита от двух одновременных бронирований

Создание заявки сериализуется PostgreSQL advisory lock по ID байка. Первая транзакция, которая захватила блокировку и создала заявку, занимает даты. Следующая заявка на пересекающиеся даты получает HTTP 409 с сообщением, что байк уже забронирован.

Ожидающая заявка (`pending`) уже удерживает выбранные даты. После подтверждения владельцем она становится активной (`active`). Если дата начала в будущем, байк не помечается физически «В аренде» заранее; этот статус выставляется с наступлением даты получения. Это сохраняет корректную доступность для будущих дат.

Подтверждение и отклонение заявок также синхронизированы тем же lock, чтобы не возникало гонок.

### 3. Фото и видео

- Новые фотографии и видео отправляются в Cloudinary, если заданы все три переменные `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`.
- В PostgreSQL сохраняются полные HTTPS URL Cloudinary; фронтенд продолжает использовать существующие поля `photos` и `videos`.
- При удалении медиа Cloudinary-ресурс удаляется по URL. Старые локальные URL `/uploads/...` продолжают обслуживаться через существующий `/uploads` mount для обратной совместимости.
- Если задана только часть Cloudinary-переменных, загрузка завершится понятной ошибкой вместо незаметного сохранения в эфемерную папку.
- Для локальной разработки без Cloudinary сохранён fallback в `UPLOAD_DIR`. На Render следует использовать Cloudinary.

- Временные preview URL в форме освобождаются, чтобы не накапливать blob URL при каждом перерисовывании.
- Добавлены проверки форматов и размера на клиенте: JPG/PNG/WEBP до 10 МБ, MP4/MOV/WEBM до 50 МБ.
- Backend сохраняет файл во временный файл и атомарно переименовывает его после полной загрузки.
- Добавление медиа к карточке использует атомарное обновление JSONB, чтобы параллельные загрузки не затирали друг друга.
- При ошибках загрузки/сохранения временные файлы удаляются.
- Для новых загрузок на Render Persistent Disk не нужен: файлы хранятся в Cloudinary. Старые файлы по локальным URL `/uploads/...` остаются зависимыми от локального диска, пока их не перенесут в Cloudinary.
- Файлы, которые уже пропали с временного диска, восстановить из одной записи URL в PostgreSQL нельзя. Их потребуется загрузить повторно после настройки постоянного хранилища.

### 4. Аналитика

- Выручка и количество аренд учитывают завершённые бронирования, дата начала которых попала в выбранный период. Вся сумма аренды (включая продления) относится к дате начала.
- Расходы берутся из таблицы `expenses` по `expense_date`.
- Фильтр по выбранному байку применяется также к расходам на графике/ленте по дням — ранее там показывались расходы всего парка.
- Загрузка байка учитывает пересечение активных и завершённых аренд с выбранным периодом; ожидающие заявки не считаются фактическими днями аренды.
- Средняя длительность аренды считается по полным завершённым арендам, начавшимся в выбранном периоде.
- Диапазон дат по умолчанию рассчитывается по календарю Вьетнама, без сдвига даты через UTC.
- В интерфейсе добавлено раскрывающееся объяснение методики расчёта.

## Cloudinary в Render

В Render → Backend → Environment должны быть добавлены три переменные (секреты не коммитить):

- `CLOUDINARY_CLOUD_NAME`
- `CLOUDINARY_API_KEY`
- `CLOUDINARY_API_SECRET`

Используйте один и тот же API Key/Secret pair из Cloudinary. После деплоя проверьте создание тестовой карточки с фотографией и видео, открытие медиа по HTTPS URL, а также удаление медиа. Не удаляйте старые файлы из Render до проверки и переноса старых URL.

## Установка

1. Сделайте резервную копию текущей папки проекта.
2. Распакуйте файлы из архива в корень проекта с заменой только перечисленных файлов.
3. В PowerShell:
   ```powershell
   cd C:\Users\User\Desktop\bike-rental\frontend
   npm run build
   ```
4. Если сборка успешна, в корне проекта проверьте:
   ```powershell
   cd C:\Users\User\Desktop\bike-rental
   git status --short
   ```
5. Сначала пришлите результат сборки и `git status --short`. Не запускайте миграции: для этого патча миграция не нужна.
